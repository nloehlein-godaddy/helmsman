# Run viewer package

This independently authored package uses type-only imports from `@helmsman/plugin-sdk`. Its runtime imports stay inside the package. It contributes `helmsman.run-viewer/page` to `helmsman/run-viewer-page` and `helmsman.run-viewer/panel` through `helmsman/run-viewer-panel@1`. Third-party replacements use their own plugin identifier and the same public contracts.

Copy this directory outside the checkout and [rename the descriptor](../../../docs/plugin-packages.md#opt-in-task-presentation-packages) before building: change `manifest.id` from the reserved `helmsman.run-viewer` to your own ID, such as `example.run-viewer`, and change its initial-layout contribution from `helmsman.run-viewer/panel` to `example.run-viewer/panel`. Keep public slot, composition and contract IDs unchanged. Install the distributed SDK as `@helmsman/plugin-sdk` plus TypeScript, run `npm run build`, then pack `dist` and install/enable the archive through the plugin CLI as shown in that recipe. The page only uses the composition service; the panel requires `helmsman/run-inspect@1`, `helmsman/run-read@1`, `helmsman/run-command@1`, `helmsman/download@1`, `helmsman/run-instructions@1` and `helmsman/postmortem@1`.

The host uses one retained session for this contribution's standalone and auxiliary surfaces. The alias follows the selected slot; a canonical viewer route opens its exact contribution. Visible rehoming preserves DOM, activity, tabs, paused logs and command evidence. Missing or disabled contributions remain unavailable without fallback. The `/runs` composition uses this shared auxiliary viewer alongside authored history and the public PR panel. Separate public PR and communication packages own their inspection and review-request workflows.

The viewer offers [live instructions](../../../docs/run-instructions.md) for supported retained local Codex/Claude sessions. Delivery receipts remain bound to the exact run attempt and target; uncertain delivery is checked without sending a duplicate. Instruction drafts and focus survive normal viewer refresh.

Failed and stopped runs offer **Ask about this failure**, a sandboxed post-mortem chat whose agent may propose patches but never applies them; the panel shows each patch's validation and the git apply command.

The viewer owns up to 12 canonical repository/run tabs. Compact tabs retain the display key, galleon and full run ID, show the PR number for reviews and branch updates, and offer an explicit new-browser-tab link; accessible names also include the observed attempt and worker status. Successful review tabs show the saved Approve, Request changes or Comment only recommendation. Inactive visible tabs refresh bounded public summaries without fetching their logs; hidden and out-of-scope tabs do not poll. Selection uses `state.presentation` and the public `selectPresentation` callback. A legacy run ID resolves inside the invoking panel's effective scope before it becomes canonical. Selecting a tab never changes the header repository. Missing selection support produces an explicit unavailable result. Tabs outside the current scope are retained and hidden; no foreign run reads or command requests are issued. At the tab limit the user closes a tab explicitly; unresolved journal requests remain visible independently of tabs.

Each log window retains at most 300 events, fetched in pages of 50 with preview text bounded at 4,000 UTF-16 code units per event. Older pagination never replaces the live-follow cursor. Following pauses for earlier browsing or when the user scrolls away from the tail. Releasing an end of a full window is disclosed; returning to that end reloads a bounded tail window. Logs are run-wide, and attempt revalidation fences reads and future command targets. An attempt change never rewrites an unresolved command's original target. Theme changes and rehoming preserve the panel, tabs, log element, focus and paused scroll; scope changes, hiding and disposal cancel reads and downloads.

Stop/retry submission uses the host journal. Receipt checking only reads a receipt. Explicit retry delivery calls optional `retry({ repo, requestId })` to read the retained original command without reserving identities. An acknowledged or missing entry sends nothing. Older hosts without this method disable Retry delivery while keeping Check request available. Requests requiring Recovery cannot be redelivered here. Accepted/rejected receipts are copied into saved panel state before acknowledgment. Failed saving leaves the journal entry intact. Up to 16 terminal results are retained; removing a saved result is an explicit user action and does not undo a command. Unsupported saved state is preserved rather than replaced.

Copy exports only the visible bounded preview. Full download invokes the sink synchronously from the click and opens `exportLog` inside the sink's lazy callback, after destination readiness. The UI distinguishes saved, delivered-to-browser and cancelled-stream results. Delivery does not confirm disk save; cancelling a stream may leave the browser's download UI pending.

Run `npx vitest run src/plugins/run-viewer` from the repository for state, lifecycle, journal and composition coverage. The source-only author build includes no tests or application imports. See [the run presentation author guide](../../../docs/run-presentation-authoring.md) for the public boundary and acceptance status.
