## Task presentation first

Todos uses source-qualified editor reads and durable commands, followed by Triage/Bugs views and source administration. The legacy generic task-source mutation endpoint returns private local records and is not the public browser contract. The new source-command port projects canonical results and durable receipts. Existing Todo mutation identities remain on their legacy compatibility path until reconciled. Never reinterpret a saved request against a new source revision or caller.

Composition pages use stateful panels for feature drafts and reuse revision-checked IndexedDB layout state. Public initial-layout declarations seed new composition records; feature defaults belong to packages. Existing records, including deliberately empty layouts, remain unchanged. Page-slot navigation is generalized while core Config and Recovery remain available.

The former 16 KiB instance-state budget could not hold valid Todo description and acceptance fields, each of which permits 20,000 characters. The shared budget is now 1 MiB per instance and 4 MiB per composition with UTF-8 and aggregate-draft coverage. It does not truncate drafts or introduce a feature-specific store. Provider editor filtering preserves the full To do category, including undescribed drafts excluded from `ready`, and applies search/filtering before pagination. Metadata carries real timestamps and nullable full filtered totals. Editor capability discovery identifies supported create/edit contracts rather than guessing from provider IDs.

The first mutation implementation must retain one logical command through response loss and concurrent tabs. Project a confirmed result as canonical task identity/revision or deletion, not a raw `LocalSourceRecord`. Prepare outside the transaction; share the actual local-record transition and durable success receipt transaction, or reconcile their recorded immutable linkage before retrying. Definite rejections are durable; uncertain work cannot be dismissed as a rejection. Acknowledge only after consuming the result and saving the affected draft.

Legacy reconciliation retains the original session request ID and exact path, method, and input. Recorded outer Todo receipts can be consumed after source disablement. Inner-only mutation receipts require the original source instance revision to verify their immutable hash; older instance revisions were not retained after configuration changes. Those requests remain explicitly blocked as `original-authority-unavailable`, with their identities preserved. Unrecorded and in-flight requests remain distinct from definite rejection. Phase G must not retire these ledgers or remap them into a new source-command request.

Acceptance includes editing during refresh/scope changes, stale record revisions, active claim locks, destination-galleon scope, response loss, terminal receipts after disable/adoption, same-intent deduplication across tabs, provider replacement, explicit unavailable metrics, and standalone SDK installation/reload.

## Run presentation and clarifications

The public run service already supplies worker outcomes, attempts, measured cost, review verdicts and separate source settlement. Extend it narrowly for permitted-scope legacy run-ID resolution, truthful history pagination metadata, bounded backward log preview, attempt-bound log cursors and watermark-bound streaming export. Add typed run/PR presentation locators rather than leaking internal route or client objects.

The legacy drawer is shared by Runs, PRs, Triage and Todos. One authored viewer must own its tabs, subscriptions, logs, clipboard/export, drafts and commands. A temporary generic mounting adapter may rehome that viewer across remaining legacy consumers; page-only extraction cannot claim the drawer owner has been removed. Keep one viewer session and suspend hidden/out-of-scope subscriptions. Core Recovery remains available with optional presentation disabled.

Clarification reads need bounded scoped DTOs. Answers require host-reserved request identity and an atomic answer-transition/receipt transaction, preserving exact question/run binding, pending state, running worker and deadline checks. Suggested-contact management is explicitly global and separate; saving a contact never sends a message. Core retains question ingestion, timeout/cancellation, answer delivery and required-answer publication gates. Preserve unfinished answers and independent contact-read failures.

Do not add a browser Resume action as part of extraction. Existing continuation keeps a run ID and increments its attempt; it cannot use the current launch/retry protocol, which creates a new run at attempt 1. Any later Resume contract must preserve checkpoint/artifact/claim/worktree verification, unresolved effects, capacity and budgets.

## Integration findings and remaining cutover gates

The new task editor and source-command services use provider-declared editor contracts. Editor input is mapped by a provider-owned preparation facet into that provider's existing mutation handlers; the host does not infer provider identity or reinterpret a UI value as a legacy command envelope. A bounded host race contains providers that ignore cancellation, and the final transaction rechecks ownership before applying a prepared mutation. Definite provider validation rejection uses a validated own-data payload, not cross-package `instanceof` identity. Authored examples currently import SDK types only; runtime helpers require explicit bundling.

Jira Bugs `asOf` is a server-generated observation time, not a historical snapshot. Provider queries retain current status and relative Jira windows; stale direct observations are rejected. Approximate counts, bounded samples, unavailable metrics and incomplete row coverage remain distinct.

Legacy Todo mutation identities remain in `helmsman.todos.pending-mutations.v1` session storage and are never reissued as new source commands. The compatibility ledger accessor checks the exact old path, method, input and UUID. Outer terminal receipts remain readable after disablement or adoption. An inner-only success can be reconciled only when the original instance revision and immutable input hash still match. Missing original authority is an explicit blocked state; preserve the UUID and evidence instead of inferring a result.

The temporary `helmsman/todo-legacy-recovery@1` host port enumerates redacted pending summaries, checks the original receipt and explicitly acknowledges confirmed terminal evidence. Nonempty journals require All-galleons panel scope because old move inputs name the destination and old deletes omit scope. Empty journals return immediately in any active scope. Corrupt or ambiguous storage is retained byte for byte. Acknowledgment checks the exact stored key and request ID again, requires a validated terminal receipt in the current service lifetime, and leaves unrelated entries intact. Changed results are bound to the original destination or the retained origin when the update omitted a destination. The authored recovery UI and isolated production proof passed, including explicit terminal dismissal and unresolved identity retention without reissue.

The public `helmsman/source-admin@1` service separates source-wide configuration, durable automatic-source selection and process-local automatic-start state. Configuration exposes only provider-declared field metadata and explicitly stored public values; absent settings remain absent so saving an unrelated field does not invent provider defaults. Hidden settings survive configuration changes. Core label, enablement and allowed-galleon configuration remains possible when the provider artifact is unavailable. Exact source and instance revisions fence configuration; schedule selection has its own revision independent of the scheduling cursor.

Configuration, scheduling and provider replacement share their actual transition transaction with immutable command receipts. Receipt reconciliation precedes current galleon availability and provider gates. Replacement validation records the caller, mode, original source/instance target, candidate artifact/provider, actor/reason and exact validation ID/evidence hash. Commit requires that complete proof and never silently refreshes stale validation.

Automatic-start toggles require the scheduler's process epoch and per-galleon revision. Legacy setters advance the same revision. A durable caller/request-ID intent reserves each toggle before changing process memory; the terminal receipt is recorded afterward. Storage failure after a toggle preserves its original identity and any in-process outcome proof, and retries reconcile that proof without toggling again. Recorded success/rejection survives restart as historical evidence. Only unresolved prior-process intents expire with an explicitly unknown historical outcome; none can enable the new process. Current runtime state is always presented separately from historical command results.

The authored source-settings presentation passed isolated installation, response-loss configuration with removal of the last allowed galleon, persistent schedule selection, restart without automatic reenablement and stale pinned replacement rejection. Source-wide settings and provider replacement remain visibly distinct from task edits. Declared settings submit a complete explicit override map: omission resets a declared field while hidden settings remain intact. Drafts retain removed schema fields for explicit reconciliation; unavailable scheduled selections remain removable. Receipt acknowledgment prunes consumed markers only after confirmation. The reusable Automatic starts panel can be composed into Todos.

## Exact-commit task-editor corrections

Review of `77c856d` found that a moved Todo could retain a related-run link under its new galleon, and that source configuration changes could strand preserved drafts at an obsolete instance revision. The host now exposes an editor run link only for an existing task and a retained run whose exact ID and galleon match the selection. The provider supplies the task association; this check establishes existence and scope, independently of Triage’s canonical-claim enrichment. Missing or failed verification yields no link.

Explicit draft reconciliation may load the latest discovered revision of the same source, instance, galleon and editor, preserving dirty fields. It cannot cross provider-instance replacement or rewrite submitted/pending source or run intent. Ordinary refresh does not silently rebase a draft after source configuration. Reconciliation and refresh are serialized so an overlapping load cannot release another operation’s busy state. Relevant package documentation describes these constraints.

The corrections passed 58 focused tests across five files, TypeScript and the production/distribution build, and all four isolated Todo production scenarios without snapshot updates. The live source-revision scenario verifies that explicit reconciliation retains unsent edits and makes the real save succeed. Exact-fix-commit reviews were clean; `bc51ae6` is pushed and its remote SHA was verified.
