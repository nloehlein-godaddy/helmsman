# Experimental page registry

This is the first increment of [Phase A](plugin-architecture-plan.md). The API is experimental and is not a published or independently installable SDK.

## What works

- Runtime validation of page contribution metadata, with immutable defensive copies.
- Atomic registration and removal, namespaced contribution IDs, and explicit slot selection.
- The existing Costs page at `/outcomes` and `/plugins/helmsman.costs/page`.
- Shared browser/server page recognition and canonical links that preserve header galleon scope.
- Explicit unavailable states for missing contributions, without substituting a different provider.
- Cancellation of pending Costs reads when leaving the page or changing its selection/scope.

Costs rendering, polling, and assessment writes still belong to the legacy host controller in `src/main.ts`. Registering another manifest makes its metadata and routes known; it does not execute code or mount a replacement page. Such pages show an unavailable state until runtime module loading and mounting are implemented.

## Manifest prototype

```json
{
  "manifestVersion": 1,
  "id": "example.costs",
  "version": "0.1.0",
  "sdkVersion": 1,
  "pages": [
    {
      "id": "summary",
      "title": "Alternative costs",
      "slots": ["helmsman/costs-page"],
      "panes": ["totals", "history"]
    }
  ]
}
```

All shown fields are required. Unsupported fields and versions are rejected. Package versions use semantic version syntax. Plugin IDs have a dotted publisher namespace; each segment and local page/pane ID uses lowercase letters, digits, and hyphens, beginning with a letter. Slot IDs use `namespace/local-id`, including core-owned `helmsman/costs-page`.

Contribution IDs combine plugin and local page IDs: `example.costs/summary`. Their canonical URL is `/plugins/example.costs/summary`; plugins cannot choose an arbitrary path that shadows a host route. Host-owned slots define aliases and default contributions separately.

This prototype covers page metadata and known pane IDs only. Entry points, capability contracts, runtime version ranges, arbitrary query-state schemas, permissions, and storage declarations are not accepted yet. They will be introduced alongside their actual consumers, before stabilizing the public manifest.

## Registry behavior

[`PluginPageRegistry`](../src/plugins/registry.ts) takes host-owned slots and reserved paths. [`parsePluginManifest`](../src/plugins/manifest.ts) accepts unknown input and returns a validated, frozen manifest or throws `PluginManifestError`. Shared types are in [`sdk.ts`](../src/plugins/sdk.ts).

| Operation | Behavior |
|---|---|
| `register(manifest)` | Validate the entire package before publishing pages; return an idempotent disposer for that registration. Duplicate plugin IDs fail. |
| `getPage(contributionId)` | Return immutable registered metadata, or `null`. |
| `resolvePath(path)` | Resolve a normalized alias or canonical path; valid missing contributions return a resolution with `page: null`. |
| `selected(slotId)` | Resolve the explicit binding, or the host default only when no binding exists. |
| `select(slotId, contributionId)` | Select a contribution that supports the slot. Explicit missing IDs remain selected and unavailable. |
| `select(slotId, null)` | Explicitly reset selection to the host default. |
| `subscribe(listener)` | Observe registry changes; return a disposer. One synchronous listener failure does not prevent others from running. |

Selection is in memory only. There is no plugin-management UI, persisted installation record, or end-user enable/disable setting in this increment. Browser and server currently initialize the same built-in registry independently; the installation/catalog protocol that will synchronize external registrations remains future work. Do not use browser-only registration as a production installation mechanism.

The host adapter recognizes the registered `helmsman.costs/page` contribution and renders its existing implementation. Generic plugin routes use an explicit `plugin` route case, not a cast into the legacy page union. The fixed Costs tab is derived from its slot. Titles remain escaped, and shell element IDs are generated by the host rather than using plugin IDs as CSS selectors.

## Validation

```sh
npm test
npm run build
npm run test:browser
```

The browser harness uses a production Vite preview with mocked APIs. It checks alias/canonical Costs rendering, header scope and reload, unavailable pages, navigation, and a visual baseline. Install its browser on a new development machine with `npx playwright install chromium`. Update snapshots only after reviewing the rendered change.

The full runnable server distribution, external package installation proof, isolated third-party execution, and durable run/provider lifecycle are not covered by this initial harness.
