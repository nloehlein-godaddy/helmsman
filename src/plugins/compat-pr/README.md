# Pull requests

This independently buildable package owns the selected `/prs` and `/pr` aliases, its canonical page, and the PR panel used by Runs. Stable IDs remain `helmsman.compat-pr/page`, `helmsman.compat-pr/panel`, and composition `helmsman/pr-compatibility-page`; existing layouts are never rewritten. Empty layouts, hidden panels and unknown state stay intact. Missing or disabled selected packages stay unavailable.

The page uses only the public composition API. The panel uses version 1 `pullRequests`, `pullRequestInspect`, `pullRequestCommands`, `runs`, and `runCommands`, with type-only SDK imports and package-local runtime dependencies. Build from a copy using the distributed SDK and TypeScript: `node build.mjs`; install `dist/plugin-package.json` with the plugin CLI.

The panel renders review-requested and authored-recent lists, explicit PR lookup (bare numbers and `#number` use the current header galleon; URLs and `owner/name#number` keep their explicit target), canonical metadata/check/review observations, immutable comparison previews, and recent PR runs. Each PR row labels approvals, changes requested, and discussion comments separately; commented review events are not folded into the discussion total. Incomplete counts stay unknown; file enumeration and patch coverage remain separate. Recent PR runs come from a bounded history sample, explicitly labeled when more history exists. Selecting a run uses the shell's shared viewer. No private renderer, host-session binding, HTTP client, execution implementation, or credential enters the package.

Legacy PR deep links use the public simultaneous `pullRequest` route hint; explicit namespaced panel route state takes precedence. Review/rerun modes focus their setup controls without submission. Pane-only links reveal inbox, authored, recent, lookup, or diff content. Selecting an explicit PR uses `setScope` for that panel and retains the header default. “Use header scope” clears the explicit target. Hiding or disposing aborts reads and subscriptions. Refresh and live list updates retain focused draft selections and open diff files.

Drafts and saved terminal results use a package-owned local-storage namespace keyed by the actual host-mounted contribution identity. Original page and Runs surfaces share the same caller's drafts; renamed panel copies use separate namespaces. Missing host identity fails before storage access. Unknown or oversized stored drafts and opaque panel state are retained. Failed draft writes retain unsaved text in the mounted panel and disable new submissions until saved. Browser storage does not provide an atomic multi-tab draft transaction: an explicit edit to the same field can supersede another tab's edit. Background reads do not write drafts.

Manual GitHub reviews bind their immutable input to the observed head. Review and rerun launches use durable public command journals. Mounting, refresh and reload read pending evidence but never submit, retry or acknowledge it automatically. Pending rows expose original input and request identity; newer drafts stay separate. Explicit receipt checks and exact retries keep the original caller/request identity. A terminal result is saved before acknowledgment; failed saves leave its request retained. Accepted launches open the shared viewer only after durable result save and acknowledgment. Recovery-required obligations link to Core Recovery.

The prior private PR drafts and pending identities were memory-only. This extraction does not import, rekey, replay, or claim restart migration for them. Server obligations remain in Core Recovery. Optional review-request controls link to the independently authored Communication page with a PR-specific target. The communication package owns durable request identity and receipts for new requests; the legacy memory-only Slack session is not imported or replayed.
