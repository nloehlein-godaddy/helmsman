# Terminal

SDK-only terminal composition page and panel. The page contribution `helmsman.terminal/page` selects `helmsman/terminal-page`, accepts `helmsman/terminal-panel@1`, and initially mounts `helmsman.terminal/panel` as instance `terminal`. The page supports `tabs` and `screen` panes. The panel requires public `helmsman/terminal@1`; no application internals or private endpoints are imported.

The terminal panel requests an explicit All scope through `setScope` before reading terminal tabs. It shows the connected terminal session independently of the header galleon selection, including tabs without a galleon association. Surface navigation preserves the separate header selection. The public typed terminal route hint also works when this package is copied under another contribution identity.

The panel lists terminals with a three-line latest-prompt preview when the service provides one, and reads a 40-line plaintext screen preview every two seconds while active. Prompt previews collapse whitespace for scanning; their tooltips retain the supplied text. Tabs without a prompt show “No prompt available.” Hiding, changing activity or tab selection, and disposing cancel reads and unsent queued controls. Tab buttons and input/output nodes remain mounted through polling, preserving keyboard focus, draft selection and scroll. Keyboard control is enabled only by an explicit click and only sends while the screen has focus; Shift+Escape releases it. Available actions come from the service. Clipboard images are bounded to 2 MiB of base64 and are sent only if the original target and activity still match after the file read.

Controls are ordered with at most 32 unsent operations. There is no retry or automatic replay. A confirmed or rejected receipt is saved before journal acknowledgment. “Check original receipt” reads the retained request without sending or establishing an inspection fence. A missing or recovery-required receipt blocks further controls on its original surface until explicit “Resume controls after inspection” invokes the public inspection service. Inspection establishes a server fence that suppresses delayed original delivery; it never resends the control. Nonpending receipts are saved before acknowledgment, and uncertainty is never presented as confirmed delivery. An active pending response, unavailable inspection, or missing inspection capability keeps the original control blocked.

Storage is namespaced by mounted contribution and instance identity. Selected surface, per-repository/surface text drafts and internal collapse preferences survive remount. Saved receipts and inspection records preserve original evidence; malformed or unsupported saved data remains untouched and blocks controls.

From the repository root: `npx vitest run src/plugins/terminal/`. Distribution tooling provides the published SDK for independent `node build.mjs` compilation.
