Assign to me

  1. Persist the original request ID and task revision.
  2. Check explicit task-action permission, source, galleon scope and task claim.
  3. Read the authenticated Jira actor and exact task: reject another assignee, confirm self-assignment without a write, or queue the declared effect for unassigned work.
  4. Pin the provider, settings and connection; recheck actor, project, revision and assignee before the Jira PUT.
  5. Retain confirmed success. Reconcile an uncertain effect without blind replay; unresolved outcomes stay in Core Recovery.
  6. Consume and dismiss the receipt, then reread before another assignment.

Jira has no atomic compare-and-set; a concurrent assignment between the final GET and PUT remains possible.

Triage disclosure

  1. Scoped task load with exact source, task and revision.
  2. Bounded plain text; preserve scoped expansion and keyboard focus.

Bugs disclosure

  1. Scoped report with optional bounded plain-text description.
  2. Persist expansion by galleon, source and task; preserve metrics and coverage.

Underway context

  1. Validate current source and task revision.
  2. Follow the exact canonical claim to a same-galleon run and expected attempt.
  3. Open the selected run presentation or its recorded PR; the target revalidates its identity.
  4. Missing associations hide actions; matching titles confer no identity.

Automatic Slack review

  1. Capture PR provider and connection; compare authenticated actor with exact-head author.
  2. Own: persist policy and block. Unknown: keep queued and retained pins.
  3. Other: recheck authority and dispatch claim before durable admission.

Firefox browser provider

  1. Independent browser selection; local WebDriver and BiDi.
  2. Fence discovered surface and session before one browser action.
  3. Lost acknowledgement remains unknown; no automatic replay.

Slack now defaults to GoCaaS/OI Companion MCP without a browser bridge. Firefox remains optional for general browser support and the explicit legacy Slack provider. Firefox does not change the terminal host or automatically replace the browser default; terminal operations are explicitly unsupported. See the Firefox README for setup and verification.

Instructions, feedback and parallel execution

Independent parallel runs

  1. Read the global cap and per-galleon policy; default to one.
  2. Require explicit opt-in and compatible ownership records.
  3. Reserve task, branch, PR and workspace before launch. Unknown or legacy identity remains exclusive.
  4. Retain unresolved ownership through retry, stop and recovery.

Live instructions

  1. Save the draft and original request for an exact attempt, channel and target.
  2. Send to a supported retained local Codex or Claude session.
  3. Record delivery only after protocol acknowledgment.
  4. Check uncertain receipts using retained evidence, including after completion; never blindly resend.

PR feedback completion

  1. Repair the existing PR and publish responses.
  2. Independently audit the current head and every feedback source.
  3. Route required decisions to Clarifications; retain answers through further repair and audit.
  4. Show completed only with current evidence. Process exit alone is insufficient.

Product feedback

  1. Configure an explicit tracker and destination; disabled by default. Restart to apply settings.
  2. Persist the scoped draft and immutable operation before submission.
  3. Show the canonical issue link after acknowledgment.
  4. Reconcile uncertain submissions without creating duplicate issues.

Agent Questions

  1. Core pins a fresh channel to each immutable execution attempt before preparation. Recovery verifies the retained channel; continuation receives a new one.
  2. The operator answers proven current-attempt questions. Delivery publishes only matching channel answers.

Review selection and concurrency

The writer and every captured reviewer must be available in the selected execution environment. Use select-agent-reviewers for the complete ordered list. Workflow policy chooses sequential lead stages; prompts request focused sub-agents, but runtime does not verify delegation.

Round and session limits

Workflow package settings allow 1–5 rounds and 5–180 minutes per session; selected agent identities determine the reviewer set. Summary correction gets one separate session per report and does not use another review round. The 2,000-character limit uses JavaScript string length, including whitespace and bylines.

Resume preserved work

A valid checkpoint verifies saved artifact hashes and its frozen snapshot, skips implementation, and reuses the original reports for its saved review round. The current branch, base, head, and complete reviewer set must match. Bound checkpoints retain original workflow, agent and host artifacts/settings with immutable manifests; legacy checkpoints retain an explicit compatibility path. Accepted corrected summaries resume from their verified corrected artifacts. Oversized saved summaries can use the same correction step.

Publication and follow-up boundaries

Pre-PR voyages have one outer attempt. Failures preserve work; a push may already have happened if a later publication check fails. Jira transitions apply to eligible Jira tasks, not todos or freeform tasks. The separate Helmsman review waits for availability and may reuse an existing review of the current head.
