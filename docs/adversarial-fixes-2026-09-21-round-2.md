## Review corrections

Cross-review of RR04 exposed an additional public lifecycle edge: an abort listener or an existing cleanup callback could register `onDispose` after the activation was marked disposed. The earlier shared-promise patch still placed that accepted callback on a fire-and-forget path. `1b27686` adds a shared bounded cleanup queue to ordinary and retained providers, with the promise installed before abort notifications. Registrations cannot extend the drain budget indefinitely.

The first TypeScript build caught a readonly-array mismatch in the new host test fixture; explicit copies now match the mutable host adapter input. The first installed Docker fixture still modeled a coordinator as an ordinary endless worker, so the strengthened wrapper correctly withheld its terminal receipt. The fixture now installs its Stop handler, reports readiness and acknowledges settlement after cleanup. It does not weaken production supervision. Its corrected installed-host run passes.

## Operational limits

- An old external host remains usable for ordinary direct work and retained discovery/Stop. Starting new staged work requires rebuilding/upgrading that host to implement and advertise coordinator protocol 1. No retained running obligation is silently rebound.
- Terminal output can report cost only after an attempt has already exceeded its cap. The fix prevents additional retries once that cost is known; it does not promise a hard real-time billing ceiling.
- Plugin cleanup remains time-bounded. A callback registered only after disposal has completed cannot reopen that completed promise; it receives bounded best-effort execution.
- Workspace ownership uses the exact stored canonical path/galleon plus current Git registration and cleanliness. A developer deliberately recreating a clean checkout at that exact historical owned path is not distinguished by a filesystem-generation token; adding such provenance is a future improvement.
- The original POSIX/Windows and deliberate-daemonization limits remain documented in the [first fix ledger](adversarial-fixes-2026-09-21.md).
