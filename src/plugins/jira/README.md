# Jira task-source plugin

A standalone backend provider built only against `@helmsman/plugin-sdk`. Copy `release/plugin-sources/jira` to an author workspace, install the released SDK and TypeScript, then run `npm run build`. Pack `dist` and install/enable through the plugin CLI. The author package registers `example.jira/issues`; configuring a source instance and its connection is separate from installing the package. Follow CLI restart instructions after backend activation changes. See [source authoring](../../../docs/task-source-authoring.md).

Jira issue IDs establish canonical identity; display keys and links may change. Source instances pin the exact provider, settings revision, permitted repositories and opaque connection handles. Credentials remain in the host. Claim/completion/abort plans use declared effects and durable host delivery; discovery and optional views receive read-only HTTP capabilities. Disabling presentation never cancels admitted work or its pinned effects.

The provider declares underway, history, Triage and Bugs views. Underway and Triage use their own assignment/status semantics independently of queue JQL. Triage exposes unassigned backlog, unassigned to-do and the configured assignee's unfinished work. Project, priority and updated-date filters precede page boundaries. Cursors bind source/revision, repository, actor, group, filters and observation window; a bounded ten-page scan may return partial coverage with continuation. Configure explicit backlog/to-do status names; legacy inference is only valid when exactly two ready statuses exist.

Bugs uses independent bounded queries and approximate counts through `jira.approximate-count/v1`. Rows are limited to 100 and show actual due dates and configured severity. Resolution P75 distinguishes the capped sample from its population. Failed metrics remain unavailable independently; an empty partial oldest query never proves absence. Observation timestamps describe current source state and recent windows, not historical reconstruction.

Declared non-secret settings cover project/repository mapping, assignment, queue JQL, statuses, bug type and severity field. Source administration returns explicit overrides separately from schema defaults. Submit the complete desired declared override map to preserve unchanged values or reset omitted keys; hidden internal settings are retained. Tokens and connection identity are not editable source settings.

[Provider view tests](views.test.ts) and the [isolated task-view gate](../../../tests/distribution/task-views-host.pw.ts) verify filters, malformed data, cursor binding, honest metrics, scope and copied-SDK compilation. E3 task presentation remains opt-in; default task routes, broader feature extraction and phases F/G are tracked in the [implementation ledger](../../../docs/plugin-implementation-progress.md).
