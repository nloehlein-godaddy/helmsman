# Pull requests

This independently buildable package owns the selected `/prs` and `/pr` aliases, its canonical page, and the PR panel used by Runs. Stable IDs remain `helmsman.compat-pr/page`, `helmsman.compat-pr/panel`, and composition `helmsman/pr-compatibility-page`; existing layouts are never rewritten. Empty layouts, hidden panels and unknown state stay intact. Missing or disabled selected packages stay unavailable.

The page uses only the public composition API. The panel uses version 1 `pullRequests`, `pullRequestInspect`, `pullRequestCommands`, `runs`, `runCommands`, and the read-only `communication.connectionStatus`, with type-only SDK imports and package-local runtime dependencies. Build from a copy using the distributed SDK and TypeScript: `node build.mjs`; install `dist/plugin-package.json` with the plugin CLI.

The panel renders review-requested and authored-recent lists, explicit PR lookup (bare numbers and `#number` use the current header galleon; URLs and `owner/name#number` keep their explicit target), canonical metadata/check/review observations, immutable comparison previews, and recent PR runs. Inspection uses the theme’s contrasting panel-high ground, list panels remain neutral, and collapsed run history recedes to the canvas. Phosphor Regular section/action/status icons are package-local, with their font and MIT license copied into independent builds. Labels preserve meaning without color: success, failure, reviews and pending work use the existing semantic green, red, blue and yellow icon roles. Title-first selection controls show eight results before a native disclosure. Each PR row labels approvals, changes requested, and discussion comments separately; commented review events are not folded into the discussion total. Unavailable and zero list counts stay out of the visual summary; detail retains unknown observations; file enumeration and patch coverage remain separate. Recent PR runs come from a bounded history sample, explicitly labeled when more history exists. Selecting a run uses the shell's shared viewer. No private renderer, host-session binding, HTTP client, execution implementation, or credential enters the package.

Open rows expose compact red **Changes requested** and blue **New comments** badges. Comment freshness compares comments from other authors against the exact latest head commit, including discussion, inline and submitted review comments. Both badges can coexist; incomplete or changed-head observations remain unknown, and closed/merged rows have no active-feedback highlight. Optional feedback evidence keeps older providers compatible. Failed search preserves independently readable scoped results with an explicit coverage notice. Server snapshots are cached for up to five minutes per credential/provider/scope; degraded reads retry sooner.

Legacy PR deep links use the public simultaneous `pullRequest` route hint; explicit namespaced panel route state takes precedence. Review/rerun modes focus their setup controls without submission. Pane-only links reveal inbox, authored, recent, lookup, or diff content. Selecting an explicit PR uses `setScope` for that panel and retains the header default. Contextual “Close inspection” clears the explicit target, its route and saved selection, then restores inherited header scope; failed closure remains available for retry. Hiding or disposing aborts reads and subscriptions. Refresh and live list updates retain focused draft selections, open diff files and disclosure state. The composed page owns one Refresh action; the standalone panel retains its own.

Drafts and saved terminal results use a package-owned local-storage namespace keyed by the actual host-mounted contribution identity. Original page and Runs surfaces share the same caller's drafts; renamed panel copies use separate namespaces. Missing host identity fails before storage access. Unknown or oversized stored drafts and opaque panel state are retained. Failed draft writes retain unsaved text in the mounted panel and disable new submissions until saved. Browser storage does not provide an atomic multi-tab draft transaction: an explicit edit to the same field can supersede another tab's edit. Background reads do not write drafts.

Manual GitHub reviews bind their immutable input to the observed head. Review and rerun launches use durable public command journals. Mounting, refresh and reload read pending evidence but never submit, retry or acknowledge it automatically. Pending rows expose original input and request identity; newer drafts stay separate. Explicit receipt checks and exact retries keep the original caller/request identity. A terminal result is saved before acknowledgment; failed saves leave its request retained. Accepted launches open the shared viewer only after durable result save and acknowledgment. Recovery-required obligations link to Core Recovery.

The prior private PR drafts and pending identities were memory-only. This extraction does not import, rekey, replay, or claim restart migration for them. Server obligations remain in Core Recovery. The Slack review link appears only for open authored PRs after a connected communication status read; absent, failed and stale reads keep it hidden. It links to the independently authored Communication page with a PR-specific target. The communication package owns durable request identity and receipts for new requests; the legacy memory-only Slack session is not imported or replayed.

Selected inspection contains labeled status evidence and optional PR context, direct agent work, the diff, then a native Your GitHub review disclosure as inset subpanels inside one shared bounty panel. Saved review text opens its disclosure on mount; disclosure state and focus survive refreshes. Duplicate Runs setup links and the account posting note are omitted. The Whiteboard companion sits within agent work.
